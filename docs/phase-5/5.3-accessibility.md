# Etapa 5.3 — Accesibilidad

Correcciones:
- Los nombres accesibles de enlaces al CV alternativo, proyectos y sitio destacado incluyen el texto visible (WCAG 2.5.3), conservando el contexto del proyecto y aviso de pestaña nueva.
- El botón móvil solo referencia aria-controls cuando su panel existe; iconos del botón son decorativos.
- Al activar movimiento reducido, Reveal oculto se hace visible mediante CSS inmediatamente. Callback idle del Hero comprueba de nuevo la preferencia para evitar cargar el shader tras un cambio de preferencia.
- `ink-subtle`: antes 5.637:1 canvas, 5.307:1 surface y 4.963:1 raised. Cumplía AA, pero no mantenía 5.31:1 en todas. Nuevo #869297: 6.096:1, 5.738:1 y 5.366:1 respectivamente. Cambio mínimo para conservar la apariencia.

Se revisaron semántica de headings, main/header/nav/footer, enlaces, botones, alt de imágenes, decoraciones aria-hidden, foco visible y skip link. CSS global reduce animaciones/transiciones y scroll; marquee se vuelve grilla y oculta duplicados; Sparkles queda estático y Hero sin WebGL.

Pruebas: teclado con Tab/Enter/Escape, foco devuelto al botón, skip link, enlaces de ancla, selector de idioma y axe WCAG 2 A/AA + 2.1 A/AA en ambos idiomas y móvil/escritorio. Resultados finales en qa/results.json. Primera ejecución detectó nombres de enlaces de proyectos que Lighthouse no penalizaba: se corrigieron antes de repetir.

Limitaciones: auditoría de escritorio Chrome con viewports emulados; no constituye certificación WCAG, ni prueba con lector de pantalla humano, Safari/iOS o dispositivos físicos. Ver informe final para resultados y pendientes.

Regresión final: los nombres del selector ES/EN incluyen sus siglas visibles; reduced-motion impone opacidad 1 y translate/transform none con !important para prevalecer sobre la capa utilities de Tailwind. Validado dinámicamente en ambos idiomas.
