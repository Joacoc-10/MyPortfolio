# Etapa 5.4 — Testing funcional y responsive

Matriz Chrome headless: ES/EN × 390, 820, 1280 y 1440 px (alto 900). Pruebas de teclado real mediante Playwright: Tab, Enter, Escape, retorno de foco, skip link; menú, idioma y recarga, PDF descargado por idioma, copia de email y anuncio de estado, destinos de anclas, imágenes, overflow, consola/hidratación y red. Axe complementa la revisión del código y la inspección visual de capturas. No hay suite de tests preexistente en package.json.

Se detectó que next-intl agregaba un Link HTTP con x-default=/ mientras HTML/sitemap decían /es, además de alternates de rutas inexistentes. alternateLinks=false elimina esta fuente duplicada; HTML y sitemap mantienen los alternates verificados. Robots index/follow se limita al home, para no contradecir el noindex automático de 404. La ruta catch-all elimina canonical/alternates de home y usa título 404 traducido.

Seguridad: Next 15.5.2 tenía avisos críticos. Actualizado a 15.5.28 con eslint-config-next alineado, transitivas compatibles actualizadas con npm audit fix sin --force y PostCSS 8.5.31 unificado por override. No se agrega una librería de aplicación. sharp resuelto a 0.35.5. Auditoría final completa: 0 vulnerabilidades conocidas (security-after.json). Referencia oficial: https://nextjs.org/blog/nextjs-security-update-october-14-2026

Los checks y métricas finales se ejecutan sobre el build con estas correcciones, no el servidor de desarrollo. Evidencia: build.txt, checks.txt, qa/results.json, capturas y after/. Scripts reproducibles en scripts/phase-5; herramientas temporales fuera de package.json del sitio.

Enlaces externos: 11 responden 200 y LinkedIn 999 (restricción automatizada), ver external-links.json. No se elimina ni reemplaza ese enlace sin verificación humana.

En la verificación final se movió toda metadata específica del inicio (canonical, alternates, robots index y OG/Twitter) desde layout a page: el error notFound podía descartar metadata de catch-all y mantener la del layout. Layout conserva solo identidad base/iconos. Se comprobó después que los 404 ya no contienen canonical ni index/follow, y que el home conserva todos sus metadatos. Selector ES/EN incluye las siglas visibles en aria-label.

Matriz de ocho casos: pasa, cero errores de consola/red y cero violaciones axe. Tras las últimas correcciones CSS/metadata se ejecutaron regresiones focalizadas: extra.json, metadata-final.json y Lighthouse final. El build limpio evitó tipos generados duplicados de compilaciones previas; ESLint y TypeScript independientes terminan con exit 0.
